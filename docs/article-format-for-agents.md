# ブログ記事の記法（外部エージェント向け）

このドキュメントは、外部エージェント（AI・自動生成ツール等）が当サイトのブログ記事を生成する際の仕様・記法をまとめたものです。  
記事を新規作成・編集する場合は、この記法に従ってください。

---

## 0. 事業別コンテンツ方針（ターゲット・トーン）

記事を作成する前に、対象事業のターゲット読者とトーンを確認してください。

### Nobilva（`relatedBusiness: nobilva`）

- **サービスの対象**: 野球をがんばる中高生とその保護者。サービスの定義文は `lib/nobilva.ts` の `NOBILVA_DEFINITION` が正式なもの
- **記事の対象**: 1本の記事は中学生向けか高校生向けのどちらか一方にする。frontmatter の `targetStage`（`junior-high` または `high-school`）で決め、1本の記事で両方を扱わない
  - 中学生向けの記事で「受験」と書いたら高校受験を指す
  - 高校生向けの記事は、高校の定期テスト・評定・大学の推薦や受験を扱う
  - 書き手の体験談は、高校時代の話なら高校生向けの記事で使う
- **読者**: 生徒向けか保護者向けかは frontmatter の `targetReader` で記事ごとに決め、本文の語りかけと CTA をそろえる
- **検索意図の背景**: 「部活と勉強を両立したい」「内申点を上げたい」「高校受験に向けて成績を上げたい」
- **トーン・文体**:
  - 中学生が読んでも理解できる平易な言葉を使う（難解な専門用語は避けるか説明を添える）
  - 落ち着いた説明の語調。励ましは記事の最後に1回まで
  - 具体的な数字・事例を用いて信頼感を出す
- **文章と構成のルール**: 3.2 と 3.5 に従う

### その他の事業

| 事業 | 主なターゲット | トーン |
| ---- | -------------- | ------ |
| `translation` | 企業・個人の翻訳依頼者 | プロフェッショナル、信頼感重視 |
| `web-design` | 中小企業・個人事業主 | 親しみやすく、実績訴求 |
| `print` | 企業の担当者 | 丁寧・具体的 |
| `teachit` | 学習者・教育関係者 | 革新的、ポジティブ |

## 1. ファイル配置

- **保存場所**: `content/blog/`
- **ファイル名**: `{slug}.md`（スラッグは英小文字・数字・ハイフンのみ、例: `soccer-study-balance.md`）
- **エンコーディング**: UTF-8
- **形式**: Markdown + YAML フロントマター（gray-matter）

---

## 2. フロントマター（必須フィールド）

記事の先頭を `---` で囲んだ YAML ブロック内にメタデータを記述します。

```yaml
---
title: "記事タイトル"
description: "記事の説明（OGP・検索結果に使用、150〜160文字推奨）"
date: "2026-02-10"
author: "Nectere編集部"
category: "学習のコツ"
categoryType: article
relatedBusiness:
  - nobilva
tags:
  - タグ1
  - タグ2
image: "/images/blog/xxx.jpg"
seo:
  primaryKeyword: "主要キーワード"
  secondaryKeywords: []
  relatedArticles: []
locale: ja
published: true
---
```

### フロントマター フィールド一覧

| フィールド              | 型       | 必須 | 説明                                             |
| ----------------------- | -------- | ---- | ------------------------------------------------ |
| `title`                 | string   | ✅   | 記事タイトル                                     |
| `description`           | string   | ✅   | 記事の説明（メタ説明・OGP用）                    |
| `date`                  | string   | ✅   | 公開日（ISO 8601: `YYYY-MM-DD`）                 |
| `author`                | string   | △    | 著者（デフォルト: `Nectere編集部`）              |
| `category`              | string   | ✅   | カテゴリ（例: 学習のコツ、お知らせ）             |
| `categoryType`          | string   | ✅   | 記事タイプ（後述）                               |
| `relatedBusiness`       | string[] | △    | 関連事業（`categoryType: article` の場合必須）   |
| `targetStage`           | string   | 任意（Nobilva 記事は必須） | `junior-high`（中学生向け）または `high-school`（高校生向け） |
| `targetSport`           | string   | 任意 | `baseball`（野球の記事）または `sports`（野球以外の競技の記事）。書いていない記事は `baseball` として扱う。`sports` の記事は記事末の箱に `NOBILVA_DEFINITION_SPORTS` を表示する（3.2 の8） |
| `tags`                  | string[] | ✅   | タグの配列                                       |
| `image`                 | string   | △    | サムネイル画像パス（例: `/images/blog/xxx.jpg`） |
| `seo.primaryKeyword`    | string   | ✅   | 主要SEOキーワード（キーワード管理画面で取得したIDを入力。例: `kw_xxx`）|
| `seo.secondaryKeywords` | string[] | ✅   | サブキーワード（**必ず3つ以上**設定する。例: `["内申点 上げる", "中学生 部活 勉強", "高校受験 スポーツ"]`） |
| `seo.relatedArticles`   | string[] | △    | 関連記事の slug 一覧（既存記事がある場合は**必ず1つ以上**設定する）  |
| `locale`                | string   | △    | 言語（デフォルト: `ja`）                         |
| `published`             | boolean  | △    | 公開可否（デフォルト: `true`）                   |

### `categoryType`（記事タイプ）

| 値              | 説明                         |
| --------------- | ---------------------------- |
| `article`       | お役立ち情報（一般的な記事） |
| `press-release` | プレスリリース               |
| `other`         | その他                       |

**重要**: `categoryType: article` の場合は `relatedBusiness` が必須です。

### `relatedBusiness`（関連事業）

`categoryType: article` の場合、少なくとも1つ指定してください。

| 値            | 説明                        |
| ------------- | --------------------------- |
| `translation` | 翻訳                        |
| `web-design`  | Web制作                     |
| `print`       | 印刷物制作                  |
| `nobilva`     | Nobilva（成績管理サービス） |
| `teachit`     | Teachit（AIに教えるアプリ） |

## 3. SEO・LLMO ライティングガイドライン

記事の品質と検索・AI両方での可視性を高めるための執筆指針です。

### 3.1 キーワード配置（SEO）

| 配置場所 | ルール |
| -------- | ------ |
| `title` | `primaryKeyword` を冒頭30文字以内に含める。全体は30〜35文字が目安 |
| `description` | `primaryKeyword` を冒頭付近に含め、タイトルの問いへの答えを1〜2文で書く。答えは1つに絞り、定義・例外・注意を並べない。「〜をまとめました」「〜を解説します」のような記事の説明は書かない。150〜160文字 |
| H1（記事冒頭の `#`） | タイトルと同一またはほぼ同じにする |
| 導入文 | 最初の100文字以内に `primaryKeyword` を自然な形で含める |
| 見出し（H2/H3） | `secondaryKeywords` を見出しに分散させる（詰め込み過ぎない） |
| 本文 | `primaryKeyword` の密度は1〜2%程度（500字に1〜2回が目安） |

`primaryKeyword` には語そのものではなく、`content/keywords.json` の `keywordGroups` に登録した ID を書く。空のまま公開しない。

### 3.2 コンテンツ構造（LLMO: LLM最適化）

AIアシスタント（ChatGPT、Gemini、Perplexityなど）に引用されやすく、人が読んでも型が見えない記事にするための指針です。

1. 導入の最初の2〜3文で、タイトルの問いに言い切って答える。書き手の立場や肩書きの紹介は導入に入れない（記事末の著者欄と構造化データに任せる。体験が答えに直接かかわる節で、その体験を書くのはよい）
2. 疑問形の見出しは1記事に2〜3個までにする。選ぶのは、Google Search Console のクエリやラッコキーワードの「よくある質問」で実際に打たれている問いだけで、残りは「野球の特待生のルール」のような名詞の見出しにする
3. 各節の最初の文は主語を入れ、見出しを読まなくても意味が通る文にする。「あります。」「各学年5人以下です。」のような、見出しの問いがないと分からない答えから始めない。AI の回答には、切り出しても意味が通る段落のほうが引かれやすい
4. 節の最初の一文を丸ごと太字にしない。FAQ の答えの最初の文も同じ。太字は文中の要所だけに使う。段落の頭を太字の1文にして見出しの代わりにする書き方もしない（h3 にするか、文の中に入れる）
5. h2 で答えた問いを、その下の h3 でもう一度答えない。h2 が問いなら h3 は名詞にする
6. タイトルの範囲の外にある話題（野球に絞っていない記事での高野連の決まり、都立の記事での他県の制度など）は、導入で範囲を事実の文で示したうえで1節に収めるか、別の記事にする。「この記事では〜を中心に」のようなメタの文で断らない（例：「野球の特待生には日本高野連の決まりがありますが、ほかの競技には全国共通の決まりはありません。」）
7. FAQ には本文で扱っていない問いだけを入れる。frontmatter の FAQ（構造化データ）と本文の FAQ は、問数も、問いと答えの文も一致させる（答えのあとに置くリンクカードや紹介の1文は一致させる対象に含めない）
8. Nobilva の定義文は本文に書かず、記事末の「Nobilva（ノビルバ）について」の箱（`lib/nobilva.ts`）に任せる。野球の記事は `NOBILVA_DEFINITION`、野球以外の競技の記事は frontmatter に `targetSport: sports` を書いて `NOBILVA_DEFINITION_SPORTS` を表示する。本文に書く場合は、箱と同じ文の最初の1文（「Nobilva（ノビルバ）は、野球をがんばる中高生のための学習管理サービスです。」または「スポーツをがんばる中高生のための」）を一字一句そのまま写す
9. 数字と時期は、読者の判断に使うものだけ具体的に書く。出典は記事末の「参考にした資料」にまとめ、本文の文の途中に資料名や公表日を括弧で挟まない。表のすぐ下に「出典：…」の行も置かない。計算した値の表には、計算のしかただけを「※〜を〜で割った値です」と1文で書く

### 3.3 コンテンツ分量の目安

| 記事種別 | 文字数（本文） | H2見出し数 |
| -------- | ------------ | ---------- |
| ピラー記事（ミドルワード） | 2,000〜3,000字 | 4〜6個 |
| クラスター記事（ロングテール） | 1,000〜1,800字 | 3〜5個 |

### 3.4 標準的な記事構成テンプレート

```
# タイトル（H1。読点を入れない。疑問形にするなら検索される問いそのもの）

導入（問いへの答え2〜3文。「この記事では〜」の目次の読み上げや、書き手の肩書きの紹介は入れない）

## 本論の h2（3〜5個。読者の疑問の順に並べる）

## よくある質問（本文にない問いを2〜3問。なければ省く）

## まとめ（読者が次にすることを3行以内。本文の入れ直しになるなら省く）

## 参考にした資料（箇条書き。日付は各行の末尾に「（2026年10月24日時点）」の形で書く）

:::cta-{事業}
```

- CTA は記事末に1つ。LINE の告知を本文の途中に置くときは、本論を読み終えた位置に置き、見出しタグを使わない
- 本のお知らせのような告知の記事は、導入で何のお知らせかを言い切り、中身（目次）、どんな人に向けたものか、入手のしかたの順に書く。よくある質問・まとめ・参考にした資料は置かない

### 3.5 文章のルール

AI が書いたように見える文の多くは、語と語の結びつき（コロケーション）の崩れと、文の長さや文末の単調さから来ます。次のルールに従ってください。

1. 地の文で作った言い方を用語のように繰り返さない（例：特待の特典、基準にクラブチームを書く、内申を点数にする、目的語のない「届く」「受け方」「区切り」「決めごと」）
2. 疑問の形の節を名詞のかわりに使わない。ふつうの名詞があればそれを使う（何のあとに机に向かうか→机に向かうタイミング、スマホをどこに置くか→スマホの置き場所、何をやるか→やること）。疑問の形のほうが自然なもの（どこでどうミスしたかを書く）は残す
3. 制度や決まりの結果としてかかる負担を、人の自発的な動作の文末で書かない（寮費は家庭が払います→寮費は家庭の負担になります／家庭が払うことになります）。読者が自分で選んでする行動や手続きの流れは「〜します」でよい
4. 可能の「〜られます」は座りが悪ければ「〜ことができます」にするか組み替える。評価を受け身で書かない（学業成績も見られます→学業成績も評価の対象になります）。「認められていません」「限られます」「充てられます」のような制度の言い方はそのままでよい
5. 強調の意図がない短い文を作らない。短い文は読者の目をそこに向けるので、前後の文とつなげる（「あります。」のような一語の答えも次の文とつなげる）。80字台までの文は長さだけを理由に切らない。文の長さの単調さは、短い文を挟むのではなく、2文をつなげる・文の組み立てを変える・文末を変えることで崩す
6. 文末に変化をつける。続く2〜3文で同じ文末にしない。段落を毎回「〜てください」「〜しましょう」で締めない
7. 一般的な説明のあとに具体例を出すときは「たとえば」で受ける。続けて例を並べるときは最初の例だけ
8. 調べた作業を本文に書かない（今回調べた範囲では、見当たらなかった→ここで挙げた学校では、表に挙げた学校の要項には）。料金や要項の時点は「2026年10月時点の料金です」のように時点だけ書く。ほかの競技や他県のように確かめきれない範囲は、「見当たらない」と書かずに「野球のような全国共通の決まりはなく、学校ごとの制度で決まります」と比べる形で書く
9. 説明のために足した比喩めいた言葉を使わない（回す、張り付く、寄りかかる、伴走、地図、手が届く、単元を埋める、土台、根っこ）。定着した慣用句はよい
10. 「〇〇ではなく」の否定で対比して強調しない。「〜のは、〜です」の倒置にしない
11. 段落の頭に予告の一文を置かない。「この記事では〜を整理しました」のようなメタの文を、本文にも description にも書かない
12. 見出しとタイトルに読点を入れない。漢字とひらがなの交ぜ書き（はく離、ちょう度）をしない
13. 同じ事実を導入・本文・FAQ・まとめで繰り返さない。繰り返すのは、導入で問いに答える1回と、本文で詳しく説明する1回まで
14. 要項の日付・学校名・金額は、読者の判断に使うものだけ本文に書き、残りは記事末の参考資料に任せる。例に出す学校は1節に1〜2校（条件に当たる学校を全部挙げる一覧は例外）
15. 体験談は話題に合うものを1〜2つ。中学生向けの記事の根拠に、高校のブラスバンドや大学受験の体験を入れない
16. 記事の芯になる言葉は導入で1回定義し、同じ意味で使い続ける（例：「3つの進路」は入試の制度の3つ＝野球推薦・推薦入試・一般入試を指し、家庭の進め方は「3つの進め方」と呼んで分ける）
17. リード（description と導入の最初の段落）は、タイトルの問いへの答えを1つだけ言う。1文に定義・例外・注意を詰め込まない。2文まで（例：「高校野球の特待生は、野球の実績を評価した私立高校が、入学金や施設費などを免除したり奨学金を出したりする制度です。」の1文だけにし、寮費の例外や入試の注意は本文に任せる）
18. 対比や逆接の関係にある2つの節を「〜があり、〜はありません」のような連用形や「て」でつながない。「〜がありますが、〜」「一方で」のように、逆接だとわかる言葉で受ける

細かい決めごと

- 都立（公立）は「受検」「受検者」、私立は「受験」と書き分ける。都立と私立のどちらにも使う評定は「入試に使う評定」と書く
- 本文で Nobilva の料金を書くときは「月18,000円（税抜）〜」。返金保証は「入会から30日以内なら月額料金を全額返金（入会金・システム管理費・市販の教材費は対象外）」
- 他社と金額を比べるときだけ（表でも本文でも）、Nobilva はシステム管理費を含めた税込額で書き、他社も税込にそろえる
- LINE 特典の冊子の名前は「高校受験の基本のき（野球×高校受験 両立ガイド）」
- 野球以外の競技の記事では、LINE の告知を特典なし型にする（4.4）
- tags は空にしない
- 読者が自分の学校名を入れる例文の「〇〇高校」は伏せ字ではない

## 4. 本文 Markdown 記法

### 4.1 標準 Markdown

以下の Markdown 記法が利用可能です（remark-gfm 対応）:

- 見出し: `#`, `##`, `###`
- 太字: `**text**`
- italic: `*text*`
- リスト（ul / ol）
- 引用: `> quote`
- リンク: `[text](url)`
- コード: `` `code` ``, `code block`

### 4.2 画像プレースホルダー

記事に画像を挿入する場合、次の形式でプレースホルダーを記述します。  
後から編集者が Unsplash 等で画像を検索して差し替える想定です。

```
![画像の説明やキャプション](IMAGE_PLACEHOLDER:検索キーワード)
```

**例**:

```markdown
![野球の練習風景](IMAGE_PLACEHOLDER:baseball practice)
![勉強と部活の両立イメージ](IMAGE_PLACEHOLDER:student studying)
```

- `IMAGE_PLACEHOLDER:` の後は、画像検索時に使う英単語または短いフレーズ
- 日本語キーワードも可
- 記事中 1〜3 箇所程度、内容に合う場合のみ挿入（必須ではない）

### 4.3 CTA ブロック（記事末尾）

記事末尾に CTA（Call to Action）ブロックを挿入します。  
複数行形式を推奨します。

- `title` / `description` 内で改行したい位置に **‖**（U+2016）を入れると、その位置で改行されます。

```
:::{cta-type}
title: CTAのタイトル
description: CTAの説明文（改行位置に‖を入れる）
button: ボタンラベル
link: /ja/services/nobilva/diagnosis
:::
```

**利用可能な CTA タイプ**:

| タイプ               | 対象サービス                |
| -------------------- | --------------------------- |
| `:::cta-nobilva`     | Nobilva（学習管理サービス） |
| `:::cta-teachit`     | Teachit（AIに教えるアプリ） |
| `:::cta-translation` | 翻訳                        |
| `:::cta-web-design`  | Web制作                     |
| `:::cta-print`       | 印刷物制作                  |

**Nobilva 記事の CTA は、次の文面で固定する。** 料金と返金保証は CTA に書かない（サービスページに任せる）。

`targetReader: parent`（`both` も含む）の記事：

```markdown
:::cta-nobilva
title: 練習で忙しい毎日に‖合わせた‖学習プランを‖つくりませんか
description: 無料の学習面談（30分・オンライン）で、‖平日の練習や週末の試合の予定と‖いまの成績をうかがい、‖限られた時間で続けられる‖学習プランをご提案します。‖教材や別の商品の‖ご案内はしません。
button: 無料学習面談を予約する（月20名限定）
link: /ja/services/nobilva/diagnosis
:::
```

`targetReader: student` の記事は、description だけを次にする。

```
description: 無料の学習面談（30分・オンライン）で、‖平日の練習や週末の試合の予定と‖いまの成績を聞いて、‖限られた時間で続けられる‖学習プランを‖メンターが提案します。‖申し込みは‖おうちの人と‖一緒にしてください。
```

1行形式も利用可能:

```markdown
:::cta-nobilva title: タイトル description: 説明 button: ボタン link: /path :::
```

### 4.4 LINE の告知（本文の途中）

LINE の告知は `:::cta-line` で書き、本論を読み終えた位置に1つ置く。型は2つある。

- 特典カード型：野球の記事で使う。`gift: 高校受験の基本のき‖（野球×高校受験 両立ガイド）` と、記事に合わせた `title`、`button: LINEで受け取る` を書く
- 特典なし型：野球以外の競技の記事（`targetSport: sports`）で使う。`gift` は書かず、`title`、`description`、`button: LINEで友だち追加` を書く。文面は特典の冊子に触れない

どちらも `id` は `<スラッグの _ 区切り>_mid_line`、`link` は `https://lin.ee/XXwhO3b`。

## 6. ピラー-クラスター構造と内部リンク

### 6.1 キーワードの階層

- **ピラーページ（ミドルワード）**: 同じ趣旨の複数キーワードを1記事でカバー。例: 「野球推薦 成績 対策」「野球推薦 評定 対策」→ 1本の包括的な記事
- **クラスターページ（ロングテール）**: 種目・時間帯・状況を絞った細かい内容。例: 「野球 朝練 勉強 30分」「遠征 前日 勉強 時間」

### 6.2 クラスター記事の内部リンク

クラスター記事を作成する場合、親ピラーページへの内部リンクを**導入またはまとめ付近**に1箇所以上含めてください。

```markdown
野球推薦と成績対策についてもっと詳しく知りたい方は、[こちらの記事](/blog/athletic-recruitment-grade)をご覧ください。
```

- リンク先は `/blog/{ピラーのslug}` 形式
- 自然な文脈で読者を誘導する

### 6.3 カニバリズム防止

- 1キーワード1記事: 同じ primaryKeyword を複数記事で使わない
- 同じ趣旨のミドルワードは1ピラーにまとめる
- キーワード管理画面で意図グループ・競合を確認してから記事を作成する

## 7. スラッグのルール

- 英小文字・数字・ハイフンのみ（ピラー/クラスター共通）
- 正規表現: `^[a-z0-9-]+$`
- 既存スラッグとの重複は不可（衝突時は `-2`, `-3` 等で区別）
- タイトルから自動生成する例: 「サッカーと勉強の両立」→ `soccer-study-balance`

## 8. 注意事項・禁止事項

- フロントマターの YAML 構文エラーに注意（コロン後のスペース、引用符の使い方）
- `categoryType: article` の場合、`relatedBusiness` を必ず1つ以上指定すること
- **Nobilva記事の対象**: 1本の記事は中学生向けか高校生向けのどちらか一方にする（`targetStage`）。中学生向けの記事で「受験」は高校受験
- CTA ブロックは記事末尾に1つ配置（複数可だが、通常は1つ）

### 公開前チェック

コミットの前に、次をすべて確かめる。

- [ ] 画像の alt と URL に `IMAGE_PLACEHOLDER` が残っていない
- [ ] `TODO` コメントや「〜の記事で扱います」のような未完成の予告がない（写真待ちの HTML コメントは残してよい）
- [ ] 「◯月」のような伏せ字がない
- [ ] 末尾 CTA が 4.3 の文面で、link が `/ja/services/nobilva/diagnosis`
- [ ] frontmatter の FAQ と本文の FAQ の問数と、問いと答えの文が一致している
- [ ] `seo.primaryKeyword` に `keywordGroups` に登録した ID が入っている
- [ ] `targetStage` と `targetReader` が入っている
- [ ] タイトルを変えた記事は、ほかの記事からのリンクの文字列も直している（`grep -rn "<slug>" content/blog`）
- [ ] 表と本文で、学校数や金額が食い違っていない
- [ ] 本文に Nobilva の料金を書くときは「月18,000円（税抜）〜」になっている
- [ ] `targetSport: sports` の記事の `:::cta-line` に `gift` が書かれていない

- 画像は `IMAGE_PLACEHOLDER` 形式で指定し、後から差し替える運用を想定
- サムネイル画像は `public/images/blog/` に配置し、`image` には `/images/blog/xxx.jpg` 形式で指定
- **参照画像のコミット**: **/admin で記事を保存したとき**は、API が `commitFilesWithBlogImages` を使うため、記事で参照している `public/images/blog/` の画像が同じコミットに自動で含まれる。**ローカルで git commit するとき**は、ステージした `content/blog/*.md` から参照されている画像を pre-commit（lint-staged → `scripts/stage-blog-images.js`）が自動でステージする。いずれも「参照されている画像」は同じコミットに含まれる。
- 記事（`content/blog/*.md`）をコミットする際、pre-commit で `build:blog-index` が実行され、`content/blog-index.json` と `content/keywords.json` が自動で再生成・ステージされる
